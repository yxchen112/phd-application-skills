# 06 审稿迭代

每轮：独立审稿 → 逐条取舍 → 修改英文 → 同步中文 → 重建 PDF 看版面 → 向用户报告"采纳了什么、没采纳什么、为什么"。

## 1. 评分表（100 分制，来自外部审稿，按此自评和让子智能体评）

| 维度 | 满分 | 看什么 |
|---|---:|---|
| 科学问题与创新定位 | 20 | 一句话能说出科学问题；方法比较为主线服务，不喧宾夺主 |
| 物理与建模方法 | 20 | 已知结构保留、极限正确、机制证据链（提出 → 检验）清楚 |
| 验证与方法比较 | 20 | 数据三层分工、参考值来源、外推隔离、同池公平对照 |
| 计算可行性与风险控制 | 15 | 数量级、候选上限、预算退路、试点先行 |
| 文献定位与表述准确性 | 15 | 引用核实、无绝对化、无过度声称 |
| 文书结构与申请匹配 | 10 | 篇幅、主次、可读性、导师要求全覆盖 |

案例轨迹：88 → 90（补数据分工与公平对照）→ 92（压缩到 2,700 词，保住关键设计）。到 92 以后审稿人只提"压缩时丢掉的定义"和个别措辞，此时应停止大改，剩余风险属于执行层面，润色消除不了。审稿人明确说过：继续加算法不提分；把已有想法写成"数据来源清楚、比较公平、成本可控"的设计才提分；篇幅过长本身扣分。

## 2. 子智能体审稿提示词（可直接用）

> 你是该领域的资深博导兼文书专家。请审阅这份博士申请 RP（附全文）。导师给的方向和原话如下：<粘贴对照表>。请按以下维度打分（附评分表），并给出：(a) must-fix（会让导师质疑可行性或正确性的问题），(b) should-fix，(c) 文字层面的 AI 味、防御性表述、过强表述、术语前后不一致，(d) 可以删的内容。每条给出原文位置和具体改法。不要建议增加新的方法或算法，除非它是回答研究问题所必需的。最后给出"是否可以发给导师"的结论。

审稿意见回来后自己判断，不照单全收。

## 3. 外部意见的取舍规则

- 逐条标注：采纳 / 改用更好方案 / 不采纳，并写一句理由。
- **他们引用的文献和"原文说法"自己重新核实**（案例：外部意见指出 BMS 不给"每项不确定度"，查原文后确认，采纳）。
- 找成本更低的等价方案（案例：不新增全展向算例，用已有数据按外层相似性重建开发集参考值）。
- 与用户明确偏好冲突时听用户的（案例：审稿两次建议恢复"第一年之后"段落，用户之前说过不要，均未采纳；在回复里附上审稿给的那句现成英文，让用户自己决定）。
- 防止范围膨胀：每采纳一条新增设计，都要同步更新表格、样本数、时间表、预算句，否则会制造新的不一致。
- 若审稿要求的补充会让篇幅超标，把细节放进内部详细版，主版本只留一句。

## 4. 高频扣分点清单（每次定稿前过一遍）

- [ ] 导师要求逐条有回应（01 的对照表）。
- [ ] 研究问题、假设、成功标准相互对应；假设不写成结论。
- [ ] 数据三层分工、参考值来源、外推隔离写清楚。
- [ ] 公平对照：同一候选池、同一测试集、披露流程差异。
- [ ] 候选/算例数量有上限，算力有数量级和退路。
- [ ] 零结果有解释和效应下限；判据不循环。
- [ ] 表格与正文一致（行、数字、范围）；新增内容同步到所有地方。
- [ ] 前后表述不矛盾（例："需要更多数据"又照样训练 → 改成"作为探索性工具"）。
- [ ] 无绝对化表述、无过度声称、无"first/novel"自夸。
- [ ] 术语一致（`rp_stats.py --terms`）。
- [ ] 篇幅在预算内，详细实施细节已移出。
- [ ] 申请人经历描述已让用户确认属实。
- [ ] **压缩后对照详细版逐段 diff**，确认没丢：模型输入定义（案例：FNO 输入漏了 k⁺）、质量控制承诺（局部—总量受力一致、网格敏感性、迭代收敛）、关键参数。这些是"定义和可信度"，不是可删的实施细节。

## 5. 向用户报告的格式

先一句话结论（这轮改成什么样、几页几词），然后：采纳的修改（按主题分组）、换了做法的地方及理由、没采纳的及理由、核实过的文献点、仍未验证的事项、备份文件名。
