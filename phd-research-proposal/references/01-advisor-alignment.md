# 01 导师对齐：先弄清导师到底要什么

RP 的第一读者是导师本人。导师看 RP 时问的是三件事：他交代的事有没有被认真回应；申请人有没有看懂这个方向更深一层的问题；这个人一年里能不能真的把事做出来。

## 1. 逐条读原始材料

- 聊天截图要一张张读，不靠印象。**先标注说话人**：微信右侧绿色气泡是用户，左侧白色气泡是对方。把每条导师原话抄成列表。
- 反例（真实发生过）："symbolic regression 我自己调研了一些，就是不确定有没有其他更好的方法"是导师说的，曾被当成用户的话。这句话恰恰是导师的核心疑问：他已经知道符号回归，想知道有没有更好的方法。答错对象，整个方法部分就会只停留在"选了符号回归"。
- 导师顺口提到的人或工作（例如"某某老师组的工作"），要搜出具体是哪篇、哪个方法（案例中是一个符号回归方法，Nature Comput. Sci. 2026），核实后写进文献综述和方法对比。

## 2. 查导师背景

- 打开学校官方主页：学历、博士/博后单位、研究方向、近期论文。例：导师是叶轮机械方向博士，方向含 CFD、网格生成、AI for CFD → 他会在意方法放进求解器里是否真的好用，以及能否用到叶片上。
- 背景用来选侧重点和例子（例如引用 Sandberg 组在涡轮尾迹上的 CFD 驱动训练），不要在 RP 里写"您是 Oxford 毕业的"之类的话。

## 3. 导师要求对照表（必做，发给用户确认）

| 导师原话 | 字面要求 | RP 中的回应位置 |
|---|---|---|
| LES generate data + AI trained wall function | 数据来源与学习对象 | 第 2、3 步 |
| symbolic regression 可能最直接，看看 FNO 等方法 | 方法比较 | 文献综述"Choosing the learning method"、第 3 步 |
| Reynolds number 先从低的开始 | 难度递进 | 试点 Re_τ=180 → 395/590 → 1000，表 1 |
| 求解器怎么选也考虑一下 | 工具论证 | 3.1 节"两类任务两种求解器" |
| （用户自己说的）把整个流程打通 | 端到端 | 试点走完从生成表面到 OpenFOAM 壁面函数 |

每一行都必须能在 RP 里指到具体段落。缺一行就是硬伤。

## 4. 从字面要求推到深层意图

对每条要求问一句"他为什么这么说"：

- "有没有比符号回归更好的方法" → 他不确定，希望你帮他把问题想清楚 → 不能只选一个方法，要按交付物的要求比较各方法族，并把"怎么选"本身做成可检验的研究内容（例如同一候选池里比较"按拟合选"和"按求解器表现选"）。
- "Re 从低到高" → 控制风险、先打通 → 试点阶段测成本和噪声，再定规模。
- "求解器怎么选" → 他关心工程落地 → 生成数据和测试公式分开选工具，测试放在工业通用求解器里。
- 导师做叶轮机械 → 意义部分点到叶片和工程求解器，但主线仍是这个项目本身。

## 5. 申请人匹配（只写真实的）

- 列出用户真实的经历与项目的对应关系（例：算子学习里嵌入物理约束 → 把极限写进公式模板；高阶有限差分 → Xcompact3d；OpenFOAM 减阻 → 壁面函数实现平台）。
- 用户缺的经验（例如没做过壁湍流 LES）不在 RP 里自曝，用"试点阶段先复现文献算例"在方案里覆盖掉。
- 3.5 节"Feasibility and Research Fit"控制在 3–4 句。个人经历描述发出前让用户逐条确认属实。

## 6. 对齐阶段的输出

给用户：导师背景三行摘要、要求对照表、深层意图判断（2–4 条）、导师提到的第三方工作及核实链接。用户确认后再进入方法设计。
